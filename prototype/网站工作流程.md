# 个人网站工作流程（讨论稿）

参考 GhostHunter《01 工作流程》，结合本网站的静态网页、作品资料和 GitHub 发布方式整理。当前为建议流程，待讨论确认；用户当次的明确要求优先。

## 阶段

1. **需求与方案**：检查现有页面、资料和约束，说明目标与待决定的问题；重要设计提供可比较的方案，估计加载、移动端和兼容性影响。
2. **视觉与交互演示**：制作草图、分镜或独立可操作演示，明确桌面与手机视口、状态、占位素材和预期效果。方向确认后再作为正式实现的参照。
3. **详细设计**：记录页面结构、交互状态、文案、异常情况、键盘与触屏操作、性能目标及可验证的验收标准。请用户确认关键体验。
4. **实现准备**：说明影响哪些页面、脚本和资源，列出素材来源、文件体积和发布影响；重大方向或资产变更在正式实现前取得明确确认。
5. **实现**：在确认范围内修改，保留原有作品内容与可访问的普通导航。需求冲突或关键资产缺失时说明影响，先完成不受影响的部分。
6. **验证**：检查实际交互、手机与桌面布局、视频与链接、键盘操作、减弱动态效果、加载体积；对照确认的画面检查并修复，无法复现或验证的项目如实记录。
7. **交付与发布**：说明修改、测试、未验证项和后续决定。独立原型不会自动上线；正式发布按用户要求和现有 GitHub 工作方式进行，发布后核对线上版本。

小范围明确修复可以合并阶段；原型与效果演示本身可以按用户明确要求先制作。重构与新功能尽量分开，避免混淆变更。对反复调整仍未解决的问题说明尝试和差异，邀请用户决定方向。

## 假 3D 演示的参考范围

- 层次：背景、桌面、幽灵、卡牌与界面分层，以透视、轻微视差和二维变形模拟空间；不需要实时三维模型。
- 手感：指针驱动卡牌，避免浏览器原生拖拽影子；支持鼠标、触控和点击替代。
- 已确认玩法：初始三张、最多五张、抽牌、拖回牌库、击中幽灵反馈后过渡到作品；随时可通过普通导航访问内容。
- 当前演示只比较动画方式，不代表最终美术、功能完整度或性能结果；保留原片和现有网站文件。
